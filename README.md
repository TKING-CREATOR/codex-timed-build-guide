# Codex 시간 제한 과제 작업 규칙

데이터 처리, 규칙 기반 최적화, 웹 서비스가 섞인 시간 제한 과제를 Codex와 함께 풀기 위한 작업 규칙이다.
특정 문제의 풀이나 코드는 담지 않는다. 결과물은 매번 과제에 맞춰 새로 만든다.

사용: 작업 폴더에 `AGENTS.md`로 저장하거나, Codex에게 "이 파일을 읽고 따라"라고 지시한다.

---

## 1. 절대 규칙

과제 안내문이 이 문서와 충돌하면 **과제 안내문이 항상 우선**이다.

1. 과제 파일, 자료, 결과물을 외부로 보내지 않는다. `git push`, 외부 업로드, 외부 API 전송을 하지 않는다.
2. 다른 AI 서비스나 모델을 연결하지 않는다. 자동 화면 조작(Computer Use)을 쓰지 않는다.
3. 감독, 보안, 업로드 제한 설정을 바꾸거나 우회하지 않는다. 막히면 멈추고 사용자에게 알린다.
4. 외부 코드는 일부 알고리즘 참고까지만 쓴다. 결과물을 통째로 대체하지 않는다. 참고했다면 `NOTES.md`에 출처를 적는다.
5. 데이터 범위 밖의 값이나 수치를 지어내지 않는다. 실행해서 확인한 값만 보고한다.

## 2. 작업 방식

- 한 번에 결과물 하나만 만들고, 끝나면 **무엇을 실행해 어떤 결과를 얻었는지** 보고한 뒤 멈춘다.
- 사용자 승인 없이 규칙(`PLAN.md`)을 바꾸지 않는다. 모호하면 추측하지 말고 선택지와 추천을 짧게 묻는다.
- "완료"는 실행 결과가 있을 때만 쓴다. 실행하지 못했으면 못 했다고 말한다.
- 요청받지 않은 기능, 복잡한 구조, 새 라이브러리를 추가하지 않는다. 시험 환경에 이미 있는 도구를 먼저 쓴다.
- 파라미터는 `config` 한 곳에 모으고, 명령 하나로 입력부터 검증까지 다시 돌게 만든다. 도중에 요구가 바뀌어도 재실행으로 대응한다.
- 무작위를 쓰면 시드를 고정한다.

## 3. 시간표 (180분 기준, 비율로 조정)

| 단계 | 시간 | 할 일 | 완료 기준 |
|---|---|---|---|
| 1. 입력 정리 | 0~15 | 자료 품질 점검, 처리 방식 기록 | 유효 + 제외 = 전체 |
| 2. 규칙 정의 | 15~25 | 제약, 직접 정할 값, 효율 지표, 우선순위 정리 | `PLAN.md`만 읽어도 판단 가능 |
| 3. 단순한 풀이 | 25~70 | 끝까지 도는 가장 단순한 방법 구현 | 전체 데이터로 결과 CSV 생성 |
| 4. 독립 검증 | 70~90 | 제약별 위반 건수 출력 | 위반 0건, 또는 남은 위반의 이유 설명 가능 |
| 5. 화면 | 90~140 | 요구 기능만 하나씩 구현 | 실제 데이터로 동작, 무작위 5건 대조 |
| 6. 문서와 제출 | 140~180 | README 작성, 새로 실행해 확인 | 안내대로 실행하고 검증 통과 |

- **90분까지 입력부터 화면까지 조잡하게라도 이어지는 최소 버전을 만든다.** 개선은 그 다음이다.
- 지연되면 화면 꾸미기와 최적화부터 줄인다. **검증과 제출물은 줄이지 않는다.**
- 마지막 10분은 새 기능을 넣지 않는다.

## 4. 단계별 지시문

사용자는 아래 문장을 그대로 복사해 쓸 수 있다.

**1. 입력 정리**
> 자료를 읽어 파일별 행 수, 컬럼, 중복, 결측, 형식 오류, 범위 이탈, 파일 간 불일치 건수만 보고해. 아직 고치지 마.

**2. 규칙 정의**
> 문제를 읽고 필수 제약 / 빠진 값 / 모호한 점을 표로 정리해. 각 모호한 점에 선택지와 추천을 붙여. 구현은 하지 마. 내가 정한 규칙은 PLAN.md에 반영해.

**3. 단순한 풀이**
> PLAN의 규칙대로 배정 함수만 만들어. 결과는 CSV로 저장하고 못 넣은 대상은 예외 목록으로 남겨. 화면은 아직 만들지 마. 전체 데이터로 실행해서 건수를 보고해.

**4. 독립 검증**
> 배정 코드를 import하지 말고 결과 CSV와 원본만 읽어 제약별 위반 건수를 출력하는 검증 스크립트를 만들어. 일부러 틀린 샘플로 각 검사가 실패하는지도 확인해.

**5. 화면**
> 결과 CSV를 읽는 웹 화면을 만들어. 먼저 개인 조회만 구현하고, 내가 확인하면 다음 기능으로 넘어가. 배정 로직은 건드리지 마.

**6. 문서**
> README 초안을 써. 실행 방법, 직접 정한 규칙과 이유, 지표 결과, 예외, 한계를 넣어. 수치는 검증 결과에 있는 값만 쓰고, 안내대로 새 폴더에서 실행해 확인해.

**변경 요청이 왔을 때**
> 코드를 고치기 전에 영향 범위를 먼저 표로 보고해. 승인하면 영향받는 대상만 재배정하고, 전후 차이(바뀐 인원, 명단)를 파일로 남긴 뒤 검증을 다시 돌려. 지킬 수 없는 조건은 무엇을 왜 어겼는지 표시해.

## 5. 입력 자료 점검 목록

- 인코딩과 BOM, 컬럼명 공백, 대소문자
- 중복 ID, 다른 값을 가진 중복 행, 파일 사이에 한쪽에만 있는 ID
- 결측, 빈 문자열, 특수 표기(`X`, `-`, `N/A`)
- 좌표: 위도와 경도 뒤바뀜, 0값, 범위를 크게 벗어난 값
- 날짜와 시각: 형식 혼재, 없는 날짜, 시작과 종료가 뒤바뀜, **자정을 넘는 구간**
- 수치 단위 혼재, 음수, 비정상적으로 큰 값
- 허용되지 않은 코드값

처리 방식(수정 / 제외 / 예외 표시)과 건수, 근거를 기록한다. **조용히 버리지 않는다.** 전체 건수가 맞는지 끝까지 확인한다.

## 6. 규칙 정의 방법

`PLAN.md`에는 다음을 적는다.

1. **필수 제약:** 문제에 적힌 조건. 수치 그대로 옮긴다.
2. **직접 정한 값:** 문제에 없어서 정한 값과 이유.
3. **효율 지표:** 숫자로 계산되는 주 지표 1개와 보조 지표 2~3개. 다른 정의를 택하지 않은 이유도 적는다.
4. **우선순위:** 필수 제약 > 전원 처리 > 공정성/예외 최소화 > 효율처럼, 충돌 시 무엇을 먼저 지킬지.
5. **예외 처리:** 조건을 지킬 수 없는 대상을 어떻게 표시할지.

## 7. 알고리즘 선택

정교함보다 **끝까지 돌고 제약을 증명할 수 있는 방법**을 고른다. 처음엔 휴리스틱으로 시작하고, 시간이 남을 때만 개선한다.

| 상황 | 먼저 쓸 방법 |
|---|---|
| 시간대, 유형이 섞인 대상 | 먼저 그룹으로 나눠 문제를 작게 만든다 |
| 사람을 거점에 묶기 (반경 제한) | 후보 지점을 만들고 가장 많이 덮는 곳부터 고르는 그리디 집합 덮기 |
| 제약이 빡빡한 대상 | 선택지가 적은 대상부터 먼저 배정 |
| 멀리 떨어진 대상 | 가장 먼 대상부터 처리하거나 별도 거점을 두고 예외로 표시 |
| 정원 안에서 지점 묶기 | 중심 기준 방향각 정렬 후 잘라 묶기(sweep) |
| 방문 순서 정하기 | 최근접 이웃 후 2-opt |
| 시각 계산 | 도착 기준이면 거꾸로, 출발 기준이면 앞으로 계산 |

- 거리, 시간 계산은 함수 하나로 모으고 손으로 계산한 값으로 2~3건 검산한다.
- 처음부터 전체 데이터로 돌린다. 샘플에서만 맞는 코드를 믿지 않는다.
- 2분 안에 안 끝나면 입력을 그룹으로 더 나누거나 후보 수를 줄인다.

## 8. 검증 규칙

- 검증 스크립트는 풀이 코드를 import하지 않는다. 결과 파일과 원본만 읽고, 상수와 계산식도 문제 문장에서 새로 옮긴다.
- 문제의 조건 하나당 검사 하나를 만들고, **누락 대상, 중복 배정**도 검사한다.
- 각 검사가 틀린 입력에서 실제로 실패하는지 확인한다. 위반 0건을 출력하는 것만으로는 믿지 않는다.
- 코드를 고칠 때마다 전체 검증을 다시 돌린다.
- README, 화면에 나오는 수치는 검증 출력과 일치해야 한다.
- 화면 값은 무작위 5건을 CSV와 대조한다.

## 9. 작업 메모 (`NOTES.md`)

결정을 내리거나 AI 오류를 찾을 때마다 Codex는 한 줄씩 추가한다. 서술형 복습 자료이므로 **실제 있었던 일만** 쓴다.

```text
[시각] 내린 결정 또는 AI 오류 → 발견한 방법 → 수정 내용
```

다음 항목을 빠짐없이 남긴다.

- 효율 지표를 그렇게 정한 이유와 버린 대안
- 자료 문제, 처리 방식, 판단 근거
- AI가 틀린 사례와 발견 경로
- 제약 때문에 생긴 비효율과 판단
- 시간이 더 있으면 할 개선과 효과 측정 방법

## 10. 제출 전 확인

- [ ] 안내문의 제출물 목록을 한 줄씩 대조했다
- [ ] 새 폴더 또는 새 환경에서 README대로 실행된다
- [ ] 검증 스크립트 최종 결과가 저장되어 있다
- [ ] README의 수치가 검증 출력과 같다
- [ ] 예외 대상과 자료 문제가 화면에서 보인다
- [ ] 비밀키, 절대경로, 임시 파일이 없다
- [ ] 제출 버튼을 눌렀고 완료 표시까지 확인했다
